## 方向 A：工业异常检测中的新子问题

### A.0 先说结论：这个方向的"显眼位置"基本被占满了

本轮查新发现，AD 里与"高分辨率 / 算力 / 光照"相关的坑已有人系统性占位：

| 已有工作 | 占了什么 |
|---|---|
| **HiAD**（arXiv 2508.12931, 2025，代码 `cnulab/HiAD`） | 高分辨率 AD + 有限算力：双分支、多分辨率融合、**检测器池 + 自适应分配**，明确以"控制计算成本"为目标 |
| **RoBiS**（2025） | AD2 专用：滑窗裁块（1024，10% 重叠）+ 光照/噪声增广 + 自适应二值化 + SAM 精修，报告 AD2 分割 +29% |
| **Beyond Benchmark Scores**（IEEE Access 2026） | AD2 上的 resolution / spatial structure / illumination / seed / **aggregation** 单因子审计 |
| **MVTec AD 2**（IJCV 2026） | 数据集本身就为"光照变化 + 微小缺陷"设计 |

⇒ **"高分辨率 + 预算分配"、"宽幅图裁块"、"光照鲁棒"这三个说法都不再能做卖点。**

因此方向 A 只能从"现象新、方法可小"的具体缺口切入。下面两个假设都是**低到中等把握**，且标注了撞车风险。

---

### A-H1：正常样本的**多模态结构**导致的系统性过检

| 项 | 内容 |
|---|---|
| ① 具体视觉失败 | 同一工件存在多种"正常外观"（不同纹理相位、不同批次的轻微色差、镀层方向），PaDiM/PatchCore 用**单一**高斯/单记忆库建模，把"第二种正常"判成异常，表现为整齐成簇的误报 |
| ② 为什么已有方法可能解决不了 | PatchCore 的 coreset 保留的是"覆盖度"，不是"模态结构"，仍以单距离阈值判定；ReinAD/PaDiM 用单一分布。已有"多模态正常性"研究多在**逻辑异常**（MVTec LOCO）语境，与"同质纹理的多外观"不是同一问题（**此点为推测，需进一步核实**） |
| ③ 改进构想（非堆模块） | 不换主干、不加注意力：在**后处理层面**把正常特征的距离分布拟合成 **K 个分量的混合**，K 由正常样本上的**拟合优度检验**自动确定（不用测试数据）；异常判据从"距离 > τ"改为"**该距离在其所属最近分量的尾概率 < α**"。本质是把"单阈值"换成"分模态的尾概率校准" |
| ④ 数据集 | MVTec AD（15 类，免费）、VisA（免费）、MVTec LOCO（免费）；本地已有 tile；AD2 sheet_metal 已有 |
| ⑤ 4GB 可行性 | ✅ 只需在**已缓存的正常特征**上做后处理，不需要重训；PaDiM 拟合已在 1.1GB 内完成 |
| ⑥ 7 天决定性实验 | 对 3 个类别：(i) 用正常特征做聚类/混合拟合，检验"单分量 vs 多分量"的 BIC 差异；(ii) 统计误报是否**成簇集中**在某个模态；(iii) 比较"单阈值"与"分模态尾概率"在**同一批热力图**上的误报率（固定召回）。若误报不成簇、或 BIC 强烈支持单分量 → 终止 |
| ⑦ 终止条件 | ①3 个类别里 ≥2 个不支持"多模态"结构；②分模态尾概率相对单阈值在固定召回下误报下降 <20%（相对）；③该现象在 VisA 上不复现 |
| ⑧ 最可能撞车 | PatchCore 的 coreset 变体；"mixture of Gaussians for AD"类工作（**本轮未系统检索，属未验证风险**）；MVTec LOCO 的逻辑异常方法 |
| ⑨ 难度 / 规模 | 难度 **低**（纯后处理，2 天可跑通）；实验规模：3–5 个类别 + 2 个数据集 + 与 PaDiM/PatchCore 对比，适合 3 个月 |

**状态标注**：③是我们的构想；①是已知现象但"多模态正常性导致成簇误报"这一具体因果**尚未验证**；⑧的 Mixture-of-Gaussian AD 是否已有工作**未核实**。

### A-H2：缺陷"可分辨性"的**事前预测**（哪些缺陷必然漏检）

| 项 | 内容 |
|---|---|
| ① 具体视觉失败 | 同一张 4K 工业图，毫米级划痕在 256 输入下**物理上不可分辨**（占不到 1 个特征单元），系统给出"无异常"却没有任何置信提示，产线无法知道"这一块我没看清" |
| ② 为什么已有方法可能解决不了 | HiAD/RoBiS 通过裁块**提高**可分辨性，但不回答"给定预算下哪些区域必然看不清"；Beyond Benchmark Scores 分析了 defect-to-patch resolution，但是**离线基准分析**，不是逐图给出"可分辨性下界"的在线信号 |
| ③ 改进构想 | 用**特征单元尺寸 ÷ 缺陷尺度先验**构造一个与模型无关的"可分辨性上限"统计量：对每个待检区域，估计它能被该网格捕获的最小缺陷像素数，输出"本区域漏检风险"作为**拒识/转人工**信号。不训练新网络，只用几何与现有特征的局部对比度 |
| ④ 数据集 | AD2 sheet_metal（已有，缺陷尺度可算）、MVTec AD（有像素级 GT 可算尺度分布） |
| ⑤ 4GB 可行性 | ✅ 纯统计，无需训练 |
| ⑥ 7 天决定性实验 | 用已有 GT 算每个缺陷的"像素尺度"，与实际检出与否做回归；若缺陷尺度与漏检的相关性弱（Spearman ρ<0.3），说明"尺度决定漏检"这个前提不成立 → 终止 |
| ⑦ 终止条件 | ①尺度–漏检相关性弱；②"可分辨性下界"估计与实测检出率偏差 >30%；③除尺度外的因素（对比度、背景纹理）贡献更大且已被 Beyond Benchmark Scores 覆盖 |
| ⑧ 最可能撞车 | Beyond Benchmark Scores（defect-to-patch resolution 维度）；HiAD 的多分辨率分析 |
| ⑨ 难度 / 规模 | 难度 **低**，但**创新度也低，偏基准分析**；只适合 Q4 或中文核心 |

**状态标注**：①是推测（尚未统计验证）；⑧撞车风险 **高**。

## 方向 B：退化文档的 **OCR 错误区域预测 + 预算受限重处理**

### B.0 生态位判断：这是三个方向里缺口最清楚的

| 已有工作 | 做到哪一步 | 留了什么口子 |
|---|---|---|
| **DocIQ / DIQA-5000**（arXiv 2509.17012, 2025） | 文档**整图**质量评分（MOS，三维修），NR-DIQA 模型 | 整图分 ≠ 区域级错误；**不告诉你去修哪里** |
| **CG-DIQA**（Li et al. 2018） | 用字符梯度做文档质量评估，以 OCR 准确率为质量真值 | 仍是**整图**回归 |
| **DocRes**（CVPR 2024） | 统一文档复原（去扭曲/去阴影/去模糊/去摩尔纹/二值化） | 复原是"全图统一执行"，**不做区域选择、不做预算权衡** |
| **MDIQA**（2025） | 统一 IQA，多维度评估 + 复原 | 评估驱动复原，但不是"逐区域决定要不要修" |
| **Entropy Heat-Mapping**（arXiv 2505.00746, 2025） | 用 token 熵的滑窗定位 GPT-4o 的 OCR 错误热点（数学文档，proof-of-concept，有代码与标注） | **只定位、不决策**；依赖 VLM 的 token 概率，传统 OCR 引擎拿不到 |
| **ICDAR 2025 轻量级上下文驱动网络**（有代码） | **置信度 ≥ τ 就跳过重模型，否则回退 DeepSolo** | 决策单元是**文本块**、只有**二选一**回退、τ 固定、目标是换更大模型而非**复原算子** |

**⇒ 缺口：把"错误风险预测"与"多种复原算子的预期增益"联合起来，在**全局算力预算**下做逐区域分配。**
现有工作分别是"评估"、"定位"、"复原"、"二选一回退"，没有人做"多算子 × 区域 × 预算"的三维分配。

---

### B-H1：区域级 OCR 错误风险预测（免训练、图像侧）

| 项 | 内容 |
|---|---|
| ① 具体视觉失败 | 整页 OCR 的 word confidence 在**退化文档**上系统性过度自信：阴影、折痕、摩尔纹区域的置信度仍然很高，但字符实际认错；于是"按置信度过滤"漏掉了真正的错误区 |
| ② 为什么已有方法可能解决不了 | (a) OCR 引擎的 confidence 来自识别器内部 softmax，对**图像退化**不敏感（它对"看不清"和"看错了"给出相似的分布）；(b) 整图 DIQA 给出一个全局分，无法定位；(c) 熵热图依赖 VLM token 概率，Tesseract/PaddleOCR 用户用不了；(d) 块级二选一级联的粒度太粗 |
| ③ 改进构想 | **不训练深度网络**：在文本行/词框内提取一组"可解释退化指标"（笔画宽度稳定性、局部对比度、拉普拉斯方差、梯度方向一致性、背景残差），用一个**轻量校准器**（梯度提升树或逻辑回归，参数 <1e4）预测"该区域是否含 ≥1 个字符错误"。输出是**概率**而不是分数，可直接映射到"是否值得重处理"的决策阈值 |
| ④ 数据集 | 需要"图像 + 逐词 GT 文本"，可从以下构建：**FUNSD / SROIE / CORD**（洁净扫描件，可程序化加退化）、**DIQA-5000**（若可获取，含 500 真实退化源图）、DocRes 的评测集；退化用 6 类确定算子（阴影/模糊/摩尔纹/折痕/低对比/透视）合成，参数固定可复现 |
| ⑤ 4GB 可行性 | ✅ 全部是 CPU 级特征 + 树模型；PaddleOCR/Tesseract 在 4GB 显存甚至纯 CPU 都能跑。**不需要 GPU 训练** |
| ⑥ 7 天决定性实验 | 取 200–300 页（洁净原件 → 合成退化 → OCR），比较三种"错误风险"信号对"该词是否出错"的 AUC：**(a) OCR 自带 confidence**、**(b) 整图 DIQA 分数（相同的全局值）**、**(c) 我们的区域特征 + 树模型**。若 (c) 的 AUC 未显著高于 (a)（配对 Bootstrap，ΔAUC < 0.05）→ **终止** |
| ⑦ 终止条件 | ①(c) 相对 (a) 的 AUC 提升 <0.05；②提升只在合成退化上成立、在真实退化子集上消失；③"出错"主要由**语言/词表**而非图像导致（此时图像侧特征注定无效） |
| ⑧ 最可能撞车 | Entropy Heat-Mapping（2505.00746）；OCR 置信度校准类工作（**本轮未系统检索，未验证**）；ICDAR 2025 的块级级联 |
| ⑨ 难度 / 规模 | 难度 **低–中**；实验规模：1 个 OCR 引擎主用 + 1 个交叉验证、3–4 个数据集、6 类退化 × 若干强度，3 个月内可完成 |

**状态标注**：①②③为构想 + 部分已知现象；"word confidence 在真实退化下过度自信"是**待验证的核心假设**，也是本方案的生死点。

### B-H2：预算受限的**多算子区域分配**

| 项 | 内容 |
|---|---|
| ① 具体视觉失败 | 一页退化文档里，只有少数区域真的需要重处理。现有做法要么整页统一复原（浪费时间且可能损害清晰区），要么固定阈值二选一回退（无法在多个算子间选择，也不控制总预算） |
| ② 为什么已有方法可能解决不了 | DocRes 是"全图统一复原"；ICDAR 2025 级联是"文本块 + 单一回退 + 固定 τ"；两者都没有"**给定 K 次算子调用，选哪 K 个区域 × 哪个算子**"的表述 |
| ③ 改进构想 | 把它写成**背包/贪心分配**：每个候选（区域, 算子）有"预测增益 ÷ 预测成本"的比值，先按比值排序、再在预算内取前 K 个；增益由 B-H1 的风险概率 × 该算子在该退化类型上的经验增益给出，成本用实测延迟。**不做端到端强化学习**，保持可解释、可复现 |
| ④ 数据集 | 同 B-H1；额外需要"算子–退化"配对效果表（可由小规模合成实验一次性测得，不需要训练） |
| ⑤ 4GB 可行性 | ✅ 复原算子用轻量实现（CLAHE、去阴影用背景估计、去模糊用固定核），全部 CPU/小显存 |
| ⑥ 7 天决定性实验 | 固定预算 B（例如每页 10 次算子调用），比较：**均匀复原** / **固定阈值级联** / **我们的贪心分配** / **oracle（用 GT 选最优）**，指标为 CER 与"每单位预算的 CER 下降"。若贪心的 CER 与均匀复原无显著差异，或距离 oracle 很远（>50% 差距）→ **终止** |
| ⑦ 终止条件 | ①贪心 ≈ 均匀（配对 Bootstrap 无差异）；②oracle 与贪心差距 >50%，说明增益不可预测；③"算子–退化"配对效果不稳定（同一算子在同类退化上方差极大） |
| ⑧ 最可能撞车 | ICDAR 2025 级联（块级二选一）；"cheap-then-clean"这类两遍流水线（工业界已有实践，学术论文尚未见，**未验证**）；预算受限的 active perception / cascade 文献（**本轮未系统检索**） |
| ⑨ 难度 / 规模 | 难度 **中**；实验规模：1 个 OCR 引擎、3 个数据集、4 种策略对比 + 预算曲线，3–4 个月 |

**状态标注**：③是构想；"多算子 × 区域 × 预算"这一形式**未检索到完全对应论文，但不能断言不存在**（见 §四）。

## 方向 C：低光照检测的预算受限选择性处理

### C.0 结论：**这是三个方向里最拥挤的，建议否定**

本轮检索到的直接相关工作（2025 年为主）：

| 已有工作 | 做了什么 |
|---|---|
| **FDLIE-YOLO**（红外与激光工程 2025, 54(1): 20240376） | 频域低照度增强 + YOLOv8n **联合损失端到端**，ExDark mAP 80.6% |
| **LowLight-YOLOv8n**（激光与光电子学进展 2025, 62(12): 1237010） | Retinexformer 前置 + RFCAConv + 大核 + Focaler-CIoU，mAP +6.8% |
| **IIF-Det**（ACM 2025） | 光照不变特征融合 + 增强-检测联合模块，ExDark 68.9 mAP，54 FPS |
| **YOLOv8 + MEEM/IGAB**（J. Supercomputing 2025） | 多尺度边缘增强 + **光照引导注意力做区域自适应特征调制**，ExDark 49.7 mAP，170 FPS |
| **HRSL-Detect**（PReMI 2025） | **global-local 增强：只提亮暗区、不动亮区**，YOLOv8-Seg，1.2 GFLOPs |
| **RA-CE / SC-CCM**（ICAACE 2025） | 光谱补偿 + **区域自适应对比度增强** |
| **AnytimeYOLO**（arXiv 2503.17497, 2025） | 可中断推理、早退、给定算力预算下的最优退出序列（Bellman-Ford） |
| **MURAL**（RTCSA 2025） | 多分辨率 anytime 推理 + 截止时间感知调度（LiDAR 3D 检测） |
| **CF-DETR**（2025） | 截止时间约束的粗到细检测，**只在模糊/高关键区域触发精细处理** |

⇒ **"只增强部分区域"、"区域自适应"、"预算/截止时间约束下分配算力"三件事都已有明确论文。**
按任务要求，"只增强部分区域"本身不能作为创新；而这正是该方向唯一剩下的立足点。

---

### C-H1：用**检测器不确定性**（而非图像亮度）驱动增强分配

| 项 | 内容 |
|---|---|
| ① 具体视觉失败 | 低光照下增强算子对**检测**未必有益：提亮会放大噪声、破坏对小目标的判别特征，使原本能检出的暗处目标消失（"越修越差"） |
| ② 为什么已有方法可能解决不了 | 现有方法用**亮度/照度图**决定增强哪里（HRSL-Detect、RA-CE、IGAB 都是光照引导），而"哪里该增强"对检测而言应由**检测置信度的空间分布**决定；anytime 类工作（AnytimeYOLO、MURAL、CF-DETR）按延迟预算分配，不看低光照的具体退化类型 |
| ③ 改进构想 | 用**检测头输出的多尺度不确定性图**（分类熵 + 回归方差）作为"该区域是否值得二次处理"的信号，只对高不确定区域施加增强并二次推理；预算固定为"每图 N 个 patch" |
| ④ 数据集 | ExDark（7363 张，12 类，免费）、LOL / LOL-v2（配对，免费）、COCO-LowLight（用 COCO val 合成，参数固定） |
| ⑤ 4GB 可行性 | ✅ YOLOv8n 级别模型训练/推理均可；增强用轻量算子 |
| ⑥ 7 天决定性实验 | 在 ExDark 上固定预算，比较"按亮度选区域"vs"按不确定性选区域"vs"全图增强"vs"不增强"的 mAP；若不确定性策略未显著优于亮度策略（ΔmAP<0.5）→ 终止 |
| ⑦ 终止条件 | ①ΔmAP<0.5；②收益来自"多跑一次推理"而非"选对区域"（需做等算力对照）；③在第二个数据集不复现 |
| ⑧ 最可能撞车 | **CF-DETR（2025）** 已做"高不确定区域触发精细处理"；IGAB 的区域自适应调制；anytime 系列 |
| ⑨ 难度 / 规模 | 难度 中；但**撞车风险高**，且与 CF-DETR 的差异需要非常精细的论证 |

**状态标注**：③是构想；与 CF-DETR 的差异**未验证**，存在被直接覆盖的风险。

### C-H2：低光照下的**漏检风险分级**（拒识信号）

| 项 | 内容 |
|---|---|
| ① 具体视觉失败 | 低光照系统"静默失败"：某个暗区实际上什么也没看清，但检测器仍输出"无目标"，下游无法区分"确实没有"与"没看清" |
| ② 为什么已有方法可能解决不了 | 现有低光照检测工作一律以 mAP 为目标，**没有把"我没把握"作为输出**；anytime 方法给的是"还可继续算"的信号，不是"结果不可信" |
| ③ 改进构想 | 用局部信噪比 + 检测头熵 + 目标尺度先验，构造一个**逐区域的可检出性上界**，输出"漏检风险等级"，用于触发补光/转人工。属于"选择性预测"在低光照检测中的应用 |
| ④ 数据集 | ExDark + LOL；可用 GT 计算"实际漏检"作为标签 |
| ⑤ 4GB 可行性 | ✅ |
| ⑥ 7 天决定性实验 | 用已有检测结果与 GT，统计"风险等级"与实际漏检的一致性（AUROC）；若 AUROC<0.7 或与单纯"区域亮度"无差异 → 终止 |
| ⑦ 终止条件 | ①AUROC<0.7；②与亮度基线无显著差异；③需要额外标注才能训练 |
| ⑧ 最可能撞车 | selective prediction / 不确定性估计在检测中的大量已有工作（**未系统检索**） |
| ⑨ 难度 / 规模 | 难度 低，但**创新度也低**，容易被认为"把已有不确定性方法搬到低光照" |
